# Decisions: Heartbeat

## ADR Log

| Date | Decision | Rationale |
|---|---|---|
| 2026-08-29 | Initial scaffold as factory-output | Learn distributed systems the agent-native way: build Raft from scratch in Rust, from RPC through leader election, log replication, a KV store, and sharding, mirroring MIT 6.824/6.5840's lab progression (6.824 was the course's number before a renumbering to 6.5840 — see `docs/workshop-design.md`), with a custom network-simulation test harness as the deterministic gate and Coachgremlin grading the conceptual layer on top. |
| 2026-08-29 | Naming pass complete: renamed to **Heartbeat** | Human picked "Heartbeat" (Raft's own term for its liveness RPC) from candidates (Heartbeat, Term Limit, Split Brain, Quorum Native), all GitHub-slug-availability-checked under coderturtle first. GitHub repo, local dir, git remote, mind-palace mirror, and vault card all renamed same day. |
| 2026-08-29 | Module arc corrected: single-node KV service before Raft, not after | Original scoping assumed "RPC → leader election → log replication → KV store → sharding." Research into MIT 6.5840's real, current lab order (pdos.csail.mit.edu/6.5840/schedule.html) found Lab 2 (an unreplicated KV service) comes *before* Lab 3 (Raft), so bugs surfaced when wrapping the KV service in Raft (Module 07) are attributable to the Raft layer alone. See `docs/workshop-design.md`'s curriculum-anchor section. |
| 2026-08-29 | Adopted `turmoil` as the deterministic gate's network-fault-injection harness (dependency change, human-confirmed per `dependency_changes: human_required`) | Rust equivalent of 6.5840's own `labrpc`: deterministic, seeded simulation supporting packet drop, partition, latency injection, and reordering. Chosen over `madsim` (more powerful — also mocks `libc` time/entropy — but not needed yet) and over building a harness from scratch (real risk: a hand-rolled harness's own bugs become indistinguishable from a learner's Raft bugs). See `docs/workshop-design.md`'s gate-harness section. |
| 2026-08-29 | Build-log/Pages site skeleton stood up under `site/`, adapted from `borrow-native/site/`'s validated Astro-on-Pages pattern | Astro 5 with the Content Layer API (`glob()` from `astro/loaders`, entries keyed by `.id`, rendered via the imported `render(entry)` function) reading `docs/build-log/` in place; `@astrojs/mdx` kept, no React narrative components ported over (not needed for a plain maintainer journal). `astro.config.mjs` targets `https://coderturtle.github.io` with `base: "/heartbeat/"` (GitHub Pages project hosting, not a custom domain yet — that's a later, human-gated decision, same as `borrow-native`'s own CNAME PR came after its initial scaffold); every internal link is `base`-aware via `import.meta.env.BASE_URL`, verified against the built HTML. One real seed build-log entry written (`docs/build-log/2026-08-29-scaffold-and-design.md`), not auto-generated from session logs, per the Workshop Gremlin's own Risks note. `npm run build` and `npx astro check` both clean. `npm audit` found 5 vulnerabilities (3 low, 2 high), all inherited from the same `astro ^5.0.0`/`@astrojs/mdx ^4.0.0`/`@astrojs/tailwind ^6.0.0` pin `borrow-native` already carries, all requiring a major `astro` version bump (`7.2.9`, breaking) to clear via `npm audit fix --force`; plain `npm audit fix` found nothing safely fixable. Not applied unilaterally — flagged as an open, human-confirmed dependency decision in `docs/next-actions.md` rather than a heartbeat-only fix, since the same pin is shared across workshops. `.github/workflows/deploy-pages.yml` added, adapted from `borrow-native`'s, but deliberately left `workflow_dispatch`-only (no `push` trigger) so merging this skeleton to `main` cannot itself trigger a live deploy; GitHub Pages was not enabled in repo settings. |
| 2026-08-29 | Deterministic-gate design revised through three doubt-driven-development cycles (single-model + Codex cross-model each cycle) | The original "green across a fixed, published seed set" design was found overclaiming (cycle 1: circular seed-count sizing, gameable published seeds, "lower odds" mischaracterizing a sampling blind spot). The fix itself had two real bugs (cycle 2: backwards rerun-escalation logic, a wall-clock timeout contradicting the harness's own determinism rule) plus its own overclaim (finite testing narrows the space of wrong implementations, it doesn't prove correctness). Cycle 3 found a real technical error (the wrong Raft safety-property example), a forward-compatibility bug (a persisted-state check that would fail Module 06's snapshot metadata), a missing liveness fairness assumption, and confirmed the resubmission-oracle gaming risk is narrowed, not closed. Stopped at the process's 3-cycle ceiling with real findings still surfacing — named explicitly in `docs/workshop-design.md` as information that the harness-security depth isn't fully closed by a pre-content design doc, deferred honestly to Coachgremlin's committed dry-run discipline rather than forced closed here. All 9 module skeletons' gate descriptions synced from "a published set of seeds" to the corrected two-set (practice + held-out) design. See `docs/workshop-design.md`'s gate section for the full revision history. |
| 2026-08-29 | Reseeded the entire arc around one real product, `Checkout`, replacing the original generic KV-store framing | A staff-engineer-level critique found the original arc's vehicle (a generic, unnamed "sharded key-value store") undifferentiated — it's the single most well-trodden teaching vehicle in the field, including 6.5840 itself, with zero thematic connection to this workshop's own audience. `Checkout` is a distributed lock/session-ownership service (`Checkout`/`Renew`/`Return`/`Status` with lease expiry) mapping directly onto a real, already-documented problem in this factory's own `git-contract.md` (two concurrent agent sessions can't safely hold the same branch/worktree at once). Human confirmed the product concept and picked the name "Checkout" from candidates (Checkout, Dibs, Turnstile, Custody). Unlike `borrow-native`'s `relay` (one feature added every module), `Checkout`'s build-out is honestly uneven: Modules 01-02 build its foundation, Modules 03-06 build the generic Raft engine it will run on (deliberately not product-specific, matching 6.5840's own generic-Raft/specific-KV-app split), Modules 07-08 wrap and scale it. Module directories 02, 07, and 08 renamed to match (`*-checkout-service`). See `docs/workshop-design.md`'s "The shared project: `Checkout`" section and `modules/README.md`'s "One shared project" section. |
| 2026-08-29 | `Checkout`'s own product design revised through two doubt-driven-development cycles (single-model + Codex cross-model each cycle), human-stopped short of the 3-cycle ceiling | Cycle 1 found `Checkout`'s design left five hard correctness properties completely unstated: deterministic lease expiry under replication, request idempotency/dedup, stale-command fencing (a delayed command evicting the wrong holder), linearizable reads, and resource-naming ambiguity enabling lock bypass via aliasing. Cycle 2 found the cycle-1 fix itself had real internal-consistency bugs: a starvation gap (an idle lease's clock never advances), an ambiguous clock model conflating the test harness with the product, a dedup cache that could replay stale success facts across a generation boundary, a snapshot contract too weak for the state the fix itself introduced, an API signature that didn't actually carry the generation it required, and a linearizable-read option (leader-lease-read) that would have silently reintroduced the wall-clock dependency the whole design eliminates. All fixed; propagated into Modules 02, 06, 07, and 08's own skeletons. See `docs/workshop-design.md`'s "The shared project: `Checkout`" section for the full revision history and the explicitly-deferred implementation-level items. |
| 2026-08-29 | Ran a third and final doubt-driven-development cycle on `Checkout`'s design, reaching the process's own 3-cycle ceiling (single-model only; Codex cross-model explicitly skipped this cycle by human choice) | Cycle 3 found five more real, non-repeat problems in the cycle-2 fix: a dedup key scoped by client alone (not per-resource) that breaks under this service's own mainline usage (a client holding two concurrent leases); a snapshot contract that only covered active leases' generations, missing that a *freed* resource's generation counter must also persist to prevent fencing-token reuse after compaction; a genuine logical contradiction in the shard-migration property, which described the whole-Raft-group-scoped logical clock as if it were per-resource migratable state; terminology drift between "request ID" and "sequence number" for the same mechanism; and an unstated unit relationship between wall-clock `lease_duration` and the logical clock. All fixed; propagated into Modules 02, 06, 07, 08, and 09's own skeletons (the capstone's grading requirement was also strengthened: pass-count verification against both named seed sets specifically, closing a vacuous-pass loophole). Stopping condition named explicitly in `docs/workshop-design.md`: three real cycles of correction is the process's designed ceiling, not a sign the design is unfinished — the honest next test is Coachgremlin's real content-building dry runs against actual code. |
| 2026-08-29 | Module 01 content authored: real exercise, test suite, rubric, and dry run (Coachgremlin's first real content-building pass for this workshop) | Scaffolded `fixtures/checkout/` (Cargo crate; `tokio` 1.53.1, `serde`/`serde_json` for wire framing, `turmoil` pinned exactly to `0.7.2` per this workshop's own doubt-driven-development finding on seed-meaning version-coupling). Authored `src/rpc.rs` (`CheckoutRequest`/`CheckoutResponse`, stubbed `send_request`/`handle_one`) and the real deterministic-tier test suite (`tests/module_01_rpc_harness.rs`, 5 tests: healthy round-trip, latency tolerance, standing-partition error, post-repair recovery, dropped-connection error, across a published 5-seed illustrative set). Real dry run (`runs/2026-08-29-module-01-dry-run/`) found a genuine, first-of-its-kind result for this workshop: a naive `read()`-vs-`read_exact()` bug passed all 5 `cargo test` cases identically to the correct implementation — even under injected latency, a constrained `tcp_capacity`, and a 200KB payload, none of which forced turmoil to split the read — but `cargo clippy --tests -- -D warnings` caught it instantly via the deny-by-default `unused_io_amount` lint. Rubric (`modules/01-rpc-over-unreliable-network/rubric.md`) lists tests-green and clippy-clean as separate gate criteria specifically because of this finding, not as redundant checks. `cargo audit`: 0 vulnerabilities across 56 dependencies. |
| 2026-08-30 | Produced a full completion roadmap via a three-agent review chain (Fable plan → Codex CLI adversarial critique with live repo access → Opus independent re-verification and reconciliation) | Full roadmap: `docs/completion-roadmap.md`. Opus's independent verification (running the actual test suite, reading turmoil's real source, diffing `git ls-files` against raw `ls`) found real issues neither Fable nor Codex caught: Module 01's `partition_surfaces_as_an_error_not_a_hang` test is vacuous (passes against the shipped `todo!()` stubs with zero implementation); no Rust toolchain pin exists despite the workshop's own stated reproducibility requirement; the Coachgremlin ARB structural-regression gate (required for any shared-throughline-project workshop, which this is) is unimplemented; there's no plan for where the cumulative reference Raft implementation lives (Modules 03-08 build on the learner's own prior code, unlike `borrow-native`'s independent per-module fixtures) or how a stalled learner resumes; and the public repo's own `AGENTS.md` points at a `scripts/verify-project.sh` that doesn't exist in a fresh clone. Also corrected a false claim (an "agent-native manifest pilot, never built" — it was built and dry-run-verified in `terminal-velocity` on 2026-07-04) and a design contradiction neither the original docs nor Codex's defense of them resolved (the held-out-seed grading model presumes a trust boundary — Coachgremlin as a party separate from the learner — that doesn't exist when Coachgremlin is explicitly self-run). See the roadmap for the full phased plan and all corrections. |
